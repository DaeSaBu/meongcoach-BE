== 공통 요청 헤더

`/api/health`를 제외한 모든 API는 앱 정보를 헤더로 받습니다.

|===
| 헤더 | 값

| `X-App-Platform`
| `ios` 또는 `android`

| `X-App-Version`
| 앱 표시 버전 (`숫자.숫자.숫자`, 예: `2.0.0`)
|===

헤더가 없거나 플랫폼별 최소 지원 버전보다 낮으면 426(`APP_UPDATE_REQUIRED`)을, 값 형식이 틀리면 400(`APP_VERSION_INVALID`)을 반환합니다.
앱은 426을 받으면 스토어 업데이트 화면으로 이동시킵니다.

== Auth API

앱이 소셜 제공자 SDK로 로그인해 받은 자격증명을 서버가 검증하고, 우리 서비스의 JWT를 발급합니다.
스토어 심사용 테스트 계정은 이메일 로그인으로 같은 JWT를 발급받습니다.
인증이 필요한 API는 발급받은 액세스 토큰을 `Authorization: Bearer {accessToken}` 헤더로 전달해 호출합니다.
인증이 필요한 API에서 사용자를 식별하는 값은 액세스 토큰의 `sub` 클레임(회원 ID)이며, 별도 요청 헤더나 파라미터로 받지 않습니다.
리프레시 토큰은 서버가 발급 이력을 저장하며, 재발급하면 이전 토큰은 폐기됩니다(rotation). 로그아웃과 회원 탈퇴도 리프레시 토큰을 폐기합니다.

=== 회원 탈퇴

link:{swagger-ui}#/Auth/auth-withdraw[▶ Swagger에서 Try it out,window=swagger]

스토어 심사 요건(인앱 계정 삭제)을 위한 API입니다. 대상 회원은 액세스 토큰의 `sub` 클레임으로 식별하므로 경로에 회원 ID를 받지 않습니다. 온보딩을 마치지 않은 회원도 호출할 수 있습니다.
소셜·이메일 자격증명과 프로필은 삭제되고 회원 행은 탈퇴 상태로만 남습니다. 같은 소셜 계정으로 다시 로그인하면 새 회원으로 가입되어 온보딩부터 다시 진행합니다.
탈퇴 즉시 기존 액세스 토큰과 리프레시 토큰은 401로 거부되므로 클라이언트는 보관 중인 토큰을 버리고 로그인 화면으로 이동해야 합니다.
등록한 강아지·AI 리포트·학습 진도는 이 API에서 정리하지 않습니다.

Apple 계정 회원은 탈퇴 직전 Sign in with Apple로 재인증해 받은 `authorizationCode`를 본문에 실어 보내야 합니다.
서버가 이 코드로 Apple 토큰을 revoke한 뒤 탈퇴를 진행하며, revoke가 실패하면 탈퇴되지 않습니다. 코드는 5분 만료·1회용이라 실패 시 새로 받아 다시 요청합니다.
카카오·구글·이메일 회원은 본문 없이 호출합니다(보내도 무시).
응답 본문은 없습니다.

operation::auth/withdraw[snippets='http-request,request-fields,http-response']

==== 실패 응답

토큰의 회원이 존재하지 않으면 404(`USER_NOT_FOUND`)를 반환합니다.
Apple 계정 회원이 `appleAuthorizationCode` 없이 요청하면 400(`AUTH_APPLE_AUTHORIZATION_CODE_REQUIRED`),
Apple이 코드를 거부하면 400(`AUTH_INVALID_APPLE_AUTHORIZATION_CODE`), Apple과 통신하지 못하면 502(`AUTH_SOCIAL_PROVIDER_UNAVAILABLE`)를 반환합니다.

operation::auth/withdraw-error[snippets='http-response,response-fields']

== Media API

파일을 서버를 거치지 않고 스토리지에 직접 업로드하기 위한 API입니다. 이미지는 Cloudflare R2에 올립니다.
액세스 토큰 인증이 필요합니다.

AI 리포트용 영상 업로드 URL 발급은 무료 체험 횟수 검증과 함께 <<_ai_api,AI API>>에서 제공합니다.
게시글 사진·영상 업로드 URL 발급은 <<_community_api,Community API>>에서 제공합니다.

이미지 업로드는 다음 순서로 진행합니다.

1. 업로드 URL 발급 API를 호출해 `uploadUrl`과 `publicUrl`을 받습니다.
2. `uploadUrl`로 이미지를 HTTP `PUT` 합니다. 이때 `Content-Type` 헤더는 발급 요청에 보낸 값과 같아야 합니다.
3. 업로드가 성공하면 `publicUrl`을 온보딩 완료 등 후속 API 요청에 담아 등록합니다.

`target`은 `USER_PROFILE` 또는 `DOG_PROFILE`이며, 생략하면 `DOG_PROFILE`입니다.
요청에는 `contentType`만 보내며, 업로드 대상은 강아지 프로필로 고정됩니다.

== Onboarding API

로그인 후 온보딩이 필요한 사용자가 강아지를 등록하는 API입니다.
모든 온보딩 API는 액세스 토큰 인증이 필요합니다.

=== 온보딩 메타데이터 조회

link:{swagger-ui}#/Onboarding/onboarding-metadata[▶ Swagger에서 Try it out,window=swagger]

온보딩 화면에 필요한 견종, 강아지 성격과 구버전 앱의 MBTI·교육 토픽 목록을 한 번에 반환합니다.
3.2.0 앱이 사용하지 않아도 `mbtis`·`topics` 필드는 구버전 온보딩을 위해 유지합니다.
견종(`breeds`)은 등록 견종 전체이며 믹스견을 맨 앞에 두고 나머지는 한글 라벨 가나다순입니다.
각 견종의 `aliases`는 한글·영문 별칭 목록이므로, 앱은 이 목록을 받아 기기에서 견종을 검색합니다.
`aliases`에는 `label`이 들어 있지 않으므로 검색할 때 `label`과 `aliases`를 함께 비교합니다. 대소문자·띄어쓰기만 다른 별칭은 하나만 내려갑니다.

operation::onboarding/metadata[snippets='http-request,http-response,response-fields']

=== 온보딩 완료

link:{swagger-ui}#/Onboarding/onboarding-complete[▶ Swagger에서 Try it out,window=swagger]

강아지 1~5마리와 보호자 프로필을 하나의 트랜잭션으로 등록합니다.
3.2.0 앱은 강아지 한 마리만 보내며 보호자 정보와 몸무게를 생략합니다. 구버전 요청도 같은 API에서 받습니다.
강아지 이름은 필수이며 서버는 구버전 호환을 위해 최대 50자까지 허용합니다. 3.2.0 앱의 입력 제한은 12자입니다.
강아지 견종, 성별, 과거 날짜의 생년월일도 필수입니다. 강아지 성격과 프로필 이미지 URL은 선택 입력입니다.
구버전의 `nickname`, `mbti`, `profileImageUrl`, `priorTrainingTopicIds`, `trainingGoalTopicIds`,
강아지의 `weightKg`, `expectation`을 보내면 저장합니다. 몸무게를 보낼 때는 양수여야 합니다.
생략한 닉네임·사진·기대 사항은 빈 문자열, MBTI·몸무게는 null, 교육 이력·목표는 빈 목록으로 저장합니다.
보호자 사진은 본인의 `images/user-profile/`, 강아지 사진은 본인의 `images/dog-profile/` 경로만 허용합니다.
강아지가 없거나 5마리를 넘으면 400(`BAD_REQUEST`)을 반환합니다.
이미 온보딩을 완료한 회원이 다시 호출하면 409를 반환합니다.

== Training API

모든 엔드포인트는 액세스 토큰 인증이 필요합니다.
목록 응답은 배열 순서가 곧 노출 순서이므로, 클라이언트는 다시 정렬하지 않고 받은 순서대로 표시합니다.

=== 커리큘럼 리스트 조회

link:{swagger-ui}#/Training/training-curriculum-list[▶ Swagger에서 Try it out,window=swagger]

대상 토픽은 액세스 토큰으로 식별한 사용자가 마지막으로 진입한 토픽이며,
진입 기록이 없거나 기록된 토픽이 더 이상 없으면 카테고리·토픽 노출 순서 기준 첫 토픽으로 폴백합니다.

=== 커리큘럼 세부 조회

link:{swagger-ui}#/Training/training-curriculum-detail[▶ Swagger에서 Try it out,window=swagger]

커리큘럼 하나와 그 커리큘럼에 속한 레슨 목록을 조회합니다.
레슨은 노출 순서대로 정렬되어 내려가며, 각 레슨에는 액세스 토큰으로 식별한 사용자의
반복 완료 횟수(`userLessonProgress.completedCount`)가 함께 내려갑니다.
진행 기록이 없는 레슨의 완료 횟수는 0이고, 레슨이 없는 커리큘럼은 빈 배열로 내려갑니다.
커리큘럼을 만든 전문가 한 명의 이름·직함·소개·사진 URL이 `expert`로 함께 내려가며, 등록된 전문가가 없으면 `expert`는 `null`입니다.

operation::training/curriculum-detail[snippets='http-request,path-parameters,http-response,response-fields']

=== 레슨 완료

link:{swagger-ui}#/Training/training-lesson-complete[▶ Swagger에서 Try it out,window=swagger]

== AI API

훈련 영상 업로드 URL 발급과, 업로드한 영상을 AI가 분석해 만든 리포트를 조회하는 API입니다.
모든 엔드포인트에 액세스 토큰 인증이 필요합니다.
리포트는 업로드 URL을 발급하는 순간 `UPLOADING`(업로드 대기) 상태로 생성되고, 업로드가 끝나면 `PENDING`(분석 중),
분석이 끝나면 `COMPLETED` 또는 `FAILED_*` 상태로 바뀝니다.
`COMPLETED`가 아닌 리포트는 `title`과 `content`가 null입니다.

[NOTE]
.분석 완료 폴링
====
클라이언트는 리포트 목록 조회를 폴링하다가 `UPLOADING`·`PENDING`인 리포트가 없으면 멈춥니다.
리포트는 발급 즉시 목록에 나타나므로 앱이 재시작돼 `objectKey`·`reportId`를 잃어도 목록만으로 진행 중인 분석을 찾을 수 있습니다.
`uploadUrl` 유효 시간(`expiresInSeconds`) 안에 업로드가 끝나지 않은 리포트는 `FAILED_UPLOAD`로 내려갑니다.
업로드가 유효 시간을 넘겨 끝난 경우에는 업로드 완료 이벤트가 처리되기까지 잠시 `FAILED_UPLOAD`로 보이다가 `PENDING`으로 바뀔 수 있습니다.
====
`videoObjectKey`는 분석한 영상을 가리키는 S3 객체 키이며,
영상 재생 URL은 내려가지 않습니다.

AI 리포트 생성은 무료 체험으로 사용자당 총 30회까지 가능합니다.
횟수를 소진하면 영상 업로드 URL 발급이 403으로 거부됩니다.

=== AI 리포트 영상 업로드 URL 발급

link:{swagger-ui}#/AI/ai-video-upload-url[▶ Swagger에서 Try it out,window=swagger]

훈련 영상을 AWS S3에 직접 업로드하기 위한 API입니다. 무료 체험 횟수를 검증한 뒤 URL을 발급합니다.
최대 50MB(52428800바이트)까지 단일 `PUT`으로 올리며, `video/mp4`(mp4)와 `video/quicktime`(mov) 두 형식만 허용합니다.

발급과 동시에 `UPLOADING` 상태의 리포트가 만들어지고 그 `reportId`가 응답에 내려갑니다.
`reportId`를 잃어버려도 리포트 목록 조회로 다시 찾을 수 있습니다.

[IMPORTANT]
====
`uploadUrl`의 서명에는 `Content-Type`뿐 아니라 **`Content-Length`도 포함**되어 있습니다.
발급 요청의 `fileSizeBytes`와 정확히 같은 바이트 수로 `PUT`해야 하며,
`Content-Length` 없이(chunked transfer encoding) 보내면 S3가 403 `SignatureDoesNotMatch`로 거부합니다.

* React Native `fetch`에 `{uri, type, name}` 형태의 body를 넘기면 chunked로 전송되어 실패합니다.
* `react-native-blob-util`의 `RNFetchBlob.wrap(path)` 또는 Expo의
  `FileSystem.uploadAsync(url, uri, { httpMethod: 'PUT', uploadType: BINARY_CONTENT })`를 사용하세요.
* `Content-Length` 헤더를 직접 지정해도 플랫폼이 body 기준으로 덮어씁니다. 길이를 알 수 있는 body를 넘겨야 합니다.
* `fileSizeBytes`는 실제로 업로드할 파일을 stat해서 구합니다.
  URL 발급 후 압축·트랜스코딩하면 크기가 달라져 실패하므로 "압축 -> stat -> 발급 -> 즉시 PUT" 순서를 지키세요.
* `uploadUrl`이 만료되면 발급 API를 다시 호출해 새 URL을 받습니다.
====

operation::ai/video-upload-url[snippets='http-request,request-fields,http-response,response-fields']

==== 실패 응답

무료 체험 횟수(30회)를 소진하면 403(`AI_REPORT_TRIAL_EXCEEDED`)을 반환합니다.
파일 크기가 상한을 넘으면 `MEDIA_VIDEO_FILE_SIZE_EXCEEDED`, 0 이하면 `MEDIA_INVALID_VIDEO_FILE_SIZE`,
지원하지 않는 형식이면 `MEDIA_UNSUPPORTED_VIDEO_TYPE`을 400으로 반환합니다.

operation::ai/video-upload-url-error[snippets='http-response,response-fields']

NOTE: 업로드한 영상의 재생 URL 발급 API는 아직 없습니다. 비공개 버킷 운영을 확정하면 presigned GET 발급과
`objectKey` 소유자 검증을 함께 추가해야 합니다.

=== 강아지 등록

link:{swagger-ui}#/Dog/dog-register[▶ Swagger에서 Try it out,window=swagger]

온보딩 이후 강아지를 한 마리 추가로 등록합니다.
이 API는 몸무게가 필수이며, 생년월일과 교육 기대 사항은 선택 입력입니다.
견종, 성격은 온보딩 메타데이터의 `code`로 보냅니다.
목록에 없는 견종은 `breed`에 견종 이름을 그대로 보내면(최대 30자) 직접 입력한 견종으로 저장됩니다.

== Graduation API

토픽의 모든 커리큘럼을 마친 회원이 실습 영상을 올리고(실습 인증), 운영자가 판정합니다. 승인하면 토픽 수료로 표시되며 보상은 없습니다.
판정은 API가 아니라 로컬 관리자 페이지가 DB에 직접 적용합니다.

=== 토픽 실습 인증 조회

link:{swagger-ui}#/Graduation/graduation-detail[▶ Swagger에서 Try it out,window=swagger]

토픽 하나의 실습 인증 현황을 조회합니다. 제출한 적이 없어도 200을 돌려주고, 이때 `graduation`은 null입니다.

첫 페이지는 `cursor`를 생략하고, 이후에는 직전 응답의 `nextCursor`를 `cursor`로 보내 이어서 조회합니다.

=== 게시글 미디어 업로드 URL 발급

link:{swagger-ui}#/Community/community-post-media-upload-url[▶ Swagger에서 Try it out,window=swagger]

게시글에 첨부할 사진·영상을 Cloudflare R2에 직접 올리기 위한 업로드 URL을 파일 하나당 하나씩 발급합니다.
여러 파일을 첨부하면 파일 수만큼 호출합니다.

1. `mediaType`(`IMAGE`·`VIDEO`), `contentType`, `fileSizeBytes`를 보내 `uploadUrl`과 `publicUrl`을 받습니다.
2. `uploadUrl`로 파일을 HTTP `PUT` 합니다. `Content-Type` 헤더는 발급 요청의 `contentType`과 같아야 하고, 영상은 `fileSizeBytes`와 같은 크기로 올려야 합니다.
3. 업로드가 성공하면 `publicUrl`을 게시글 작성 요청에 담아 등록합니다.

사진은 `image/jpeg`·`image/png`·`image/webp`, 영상은 `video/mp4`·`video/quicktime`을 받습니다.
영상은 512MiB(536,870,912바이트) 이하만 발급하며, 사진은 크기 상한이 없습니다.
`uploadUrl`은 `expiresInSeconds`초 뒤에 만료되므로 만료되면 다시 발급받습니다.

operation::community/post-media-upload-url[snippets='http-request,request-fields,http-response,response-fields']

==== 실패 응답

`mediaType`이 지원하지 않는 종류면 400(`COMMUNITY_POST_MEDIA_TYPE_INVALID`), `contentType`이 미디어 종류에 맞지 않으면 400(`MEDIA_UNSUPPORTED_IMAGE_TYPE` 또는 `MEDIA_UNSUPPORTED_VIDEO_TYPE`)이 내려갑니다.
영상이 512MiB를 넘으면 400(`MEDIA_VIDEO_FILE_SIZE_EXCEEDED`)이 내려갑니다.
필드가 비어 있거나 `fileSizeBytes`가 양의 정수가 아니면 400(`BAD_REQUEST`)에 `errors` 필드로 항목별 원인이 내려갑니다.

operation::community/post-media-upload-url-error[snippets='http-response,response-fields']

=== 게시글 작성

link:{swagger-ui}#/Community/community-post-register[▶ Swagger에서 Try it out,window=swagger]

로그인한 회원의 커뮤니티 게시글을 작성합니다. 성공하면 201과 함께 작성한 게시글이 내려갑니다.
`content`는 필수이며 공백만으로 채울 수 없고 200자 이하입니다.
레슨을 멘션하려면 `mention`에 대상 종류(`LESSON`)와 ID를 담고, 멘션 없이 작성하면 `mention` 필드를 생략합니다.
멘션 없이 작성했으면 응답의 `mention`이 null입니다.
사진·영상을 첨부하려면 게시글 미디어 업로드 URL 발급으로 올린 파일의 `publicUrl`을 `media`에 종류(`IMAGE`·`VIDEO`)와 함께 담습니다.
사진은 3개, 영상은 2개까지 첨부할 수 있고 배열 순서가 표시 순서입니다. 첨부 없이 작성하면 `media` 필드를 생략하며, 이때 응답의 `media`는 빈 배열입니다.

operation::community/post-register[snippets='http-request,request-fields,http-response,response-fields']

==== 실패 응답

`content`가 비어 있거나 200자를 넘으면 400(`COMMUNITY_POST_CONTENT_INVALID`), `mention.targetType`이 지원하지 않는 종류면 400(`COMMUNITY_MENTION_TARGET_TYPE_INVALID`)이 내려갑니다.
`mention.targetType`이 비어 있거나 `mention.targetId`가 양의 정수가 아니면 400(`BAD_REQUEST`)에 `errors` 필드로 항목별 원인이 내려갑니다.
멘션한 레슨이 없으면 404(`COMMUNITY_MENTION_TARGET_NOT_FOUND`)가 내려갑니다.
`media[].type`이 지원하지 않는 종류면 400(`COMMUNITY_POST_MEDIA_TYPE_INVALID`), 사진이 3개나 영상이 2개를 넘으면 400(`COMMUNITY_POST_MEDIA_COUNT_EXCEEDED`)이 내려갑니다.
`media[].url`이 본인이 게시글 용도로 올린 같은 종류의 파일이 아니면 400(`MEDIA_INVALID_URL`)이 내려갑니다. `media[].type`·`media[].url`이 비어 있으면 400(`BAD_REQUEST`)에 `errors` 필드로 항목별 원인이 내려갑니다.

=== 커스텀 플랜 생성

link:{swagger-ui}#/Plan/plan-custom-create[▶ Swagger에서 Try it out,window=swagger]

로그인한 회원의 선택된 강아지로 커스텀 플랜을 생성합니다. 성공하면 201과 생성된 `planId`를 반환합니다.
선택한 1~3개 토픽의 커리큘럼을 교육 순서로 합친 뒤, 첫 미완료 커리큘럼부터 이후의 모든 커리큘럼을 포함합니다.
첫 미완료 커리큘럼 앞의 완료된 커리큘럼은 제외하고, 뒤의 완료된 커리큘럼은 포함해 다시 학습합니다.
제목은 `{강아지 이름}의 2주 훈련 플랜`, 목표는 `선택한 훈련을 차근차근 익혀요`입니다.
기존 활성 플랜은 새 플랜 생성에 성공할 때 교체하며, 실패하면 유지됩니다.
하루 훈련 시간과 주당 훈련 일수는 저장하며, 훈련량 제한이나 자동 만료에 사용하지 않습니다.

=== AI 플랜 생성

link:{swagger-ui}#/Plan/plan-ai-create[▶ Swagger에서 Try it out,window=swagger]

`POST /api/plans/ai`는 로그인한 회원의 선택된 강아지와 훈련 기대사항으로 플랜을 생성합니다.
성공하면 201과 생성된 `planId`를 반환합니다. 강아지 ID와 토픽 ID는 요청에서 받지 않습니다.
`expectation`은 공백이 아닌 내용이 필수이며 최대 500자입니다. 입력값은 플랜에 그대로 저장합니다.
강아지 생년월일은 월령으로 변환하지 않고 한국 날짜 기준 생성일과 함께 AI에 전달합니다.

AI는 필요한 토픽과 목표 문장을 생성하며 제목은 커스텀과 같은 `{강아지 이름}의 2주 훈련 플랜`입니다.
선택한 토픽의 커리큘럼을 교육 순서로 합친 뒤 첫 미완료부터 끝까지 포함합니다.
이후에 이미 완료한 커리큘럼도 다시 포함하며 일반 학습 완료 횟수는 변경하지 않습니다.
AI 플랜의 새 훈련 분량은 2주 총 연습 시간의 50%에 더 가까운 구성을 선택하고, 차이가 같으면 적은 분량을 선택합니다.
이는 AI 선택 지침이며 서버의 시간 상한 검증이나 반복횟수 계산은 아닙니다.

AI 호출은 DB 트랜잭션 밖에서 실행하고, 기존 활성 플랜 교체와 새 플랜 저장은 같은 트랜잭션으로 처리합니다.
AI 생성 또는 저장에 실패하면 기존 활성 플랜을 유지합니다. 자동 재시도하지 않습니다.

operation::plan/ai-create[snippets='http-request,request-fields,http-response,response-fields']

==== 실패 응답

인증 정보가 없으면 401(`UNAUTHORIZED`)을 반환합니다.
필수 값 누락, 공백 기대사항, 500자 초과는 400(`BAD_REQUEST`)을 반환합니다.
하루 훈련 시간은 5, 10, 20만 허용하며 그 외 값은 400(`PLAN_INVALID_DAILY_MINUTES`)을 반환합니다. 20은 20분 이상을 뜻합니다.
주당 훈련 일수는 3, 5, 7만 허용하며 그 외 값은 400(`PLAN_INVALID_DAYS_PER_WEEK`)을 반환합니다.
이 입력값은 AI 호출 전에 검증합니다.
선택된 강아지가 없으면 404(`DOG_NOT_FOUND`)를 반환합니다.
미완료 커리큘럼 후보가 없으면 AI를 호출하지 않고 400(`PLAN_EMPTY_CURRICULUMS`)을 반환합니다.
AI 호출 후 다시 확인한 선택 토픽에 미완료 커리큘럼이 없는 경우도 같은 오류를 반환합니다.
외부 AI 호출 실패는 502(`AI_CONTENT_GENERATION_FAILED`), 잘못된 AI 결과는 502(`PLAN_AI_INVALID_RESPONSE`)를 반환합니다.
저장 중 데이터 무결성 위반은 409(`PLAN_CREATION_CONFLICT`)를 반환합니다.

=== 현재 플랜 조회

활성 플랜을 우선 반환하고, 없으면 완료 시각이 가장 최근인 플랜을 반환합니다.
완료 시각이 같으면 ID가 큰 플랜을 반환하며, 교체된 플랜은 반환하지 않습니다.
`completedAt`은 UTC 기준 ISO 8601 문자열(`2026-10-25T12:00:00Z`)이며, 미완료 상태에서는 null입니다.
둘 다 없으면 `200 OK`와 `{"plan": null}`을 반환합니다.

완료된 플랜(`status: COMPLETED`)은 커리큘럼 조회와 진도 계산을 생략하고 `curriculums: []`를 반환합니다.
프론트에서는 상세 진도 대신 완료 안내와 '다음 플랜 만들기' 버튼을 표시합니다.
저장된 커리큘럼 ID와 완료 레슨 ID는 유지하며, 이후 교육 콘텐츠가 변경되어도 완료 상태는 유지합니다.

진행 중인 플랜의 커리큘럼은 플랜에 저장한 순서로, 레슨은 교육 순서로 반환합니다.
카드 하나는 커리큘럼 하나이며, 제목과 설명은 기존 훈련 콘텐츠를 사용합니다.
진도는 현재 교육 목록과 이 플랜에서 완료한 레슨 ID를 기준으로 계산합니다.
일반 커리큘럼 화면이나 다른 플랜의 완료 기록은 반영하지 않습니다.
현재 목록에서 빠진 레슨은 완료 수에서 제외하고, 추가된 레슨은 이 플랜의 완료 기록에 없으면 미완료로 표시합니다.
`locked`는 이용권에 따른 표시용입니다.
잠긴 커리큘럼도 목록에 포함하고 실제 레슨 접근 제한은 기존 API에서 검사합니다.
이 조회는 플랜 상태를 변경하지 않습니다.

`POST /internal/notifications/dispatch`는 예약 시각·발송 시각으로 알림을 발송합니다.
같은 예약 시각·hour가 진행 중이거나 완료됐으면 `duplicate=true`로 응답합니다.
실패한 예약은 같은 키로 다시 실행할 수 있습니다.
