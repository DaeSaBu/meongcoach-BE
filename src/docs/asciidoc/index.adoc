== Auth API

앱이 소셜 제공자 SDK로 로그인해 받은 자격증명을 서버가 검증하고, 우리 서비스의 JWT를 발급합니다.
인증이 필요한 API는 발급받은 액세스 토큰을 `Authorization: Bearer {accessToken}` 헤더로 전달해 호출합니다.

== Media API

파일을 서버를 거치지 않고 스토리지에 직접 업로드하기 위한 API입니다. 이미지는 Cloudflare R2에 올립니다.
액세스 토큰 인증이 필요합니다.

AI 리포트용 영상 업로드 URL 발급은 무료 체험 횟수 검증과 함께 <<_ai_api,AI API>>에서 제공합니다.

이미지 업로드는 다음 순서로 진행합니다.

1. 업로드 URL 발급 API를 호출해 `uploadUrl`과 `publicUrl`을 받습니다.
2. `uploadUrl`로 이미지를 HTTP `PUT` 합니다. 이때 `Content-Type` 헤더는 발급 요청에 보낸 값과 같아야 합니다.
3. 업로드가 성공하면 `publicUrl`을 온보딩 완료 등 후속 API 요청에 담아 등록합니다.

== AI API

훈련 영상 업로드 URL 발급과, 업로드한 영상을 AI가 분석해 만든 리포트를 조회하는 API입니다.
모든 엔드포인트에 액세스 토큰 인증이 필요합니다.
리포트는 업로드 URL을 발급하는 순간 `UPLOADING`(업로드 대기) 상태로 생성되고, 업로드가 끝나면 `PENDING`(분석 중),
분석이 끝나면 `COMPLETED` 또는 `FAILED_*` 상태로 바뀝니다.
`COMPLETED`가 아닌 리포트는 `title`과 `content`가 null입니다.

[NOTE]
.분석 완료 폴링
====
클라이언트는 리포트 목록 조회를 폴링하다가 `UPLOADING`·`PENDING`인 리포트가 없으면 멈춥니다.
리포트는 발급 즉시 목록에 나타나므로 앱이 재시작돼 `objectKey`·`reportId`를 잃어도 목록만으로 진행 중인 분석을 찾을 수 있습니다.
`uploadUrl` 유효 시간(`expiresInSeconds`) 안에 업로드가 끝나지 않은 리포트는 `FAILED_UPLOAD`로 내려갑니다.
업로드가 유효 시간을 넘겨 끝난 경우에는 업로드 완료 이벤트가 처리되기까지 잠시 `FAILED_UPLOAD`로 보이다가 `PENDING`으로 바뀔 수 있습니다.
====
`videoObjectKey`는 분석한 영상을 가리키는 S3 객체 키이며,
영상 재생 URL은 내려가지 않습니다.

AI 리포트 생성은 무료 체험으로 사용자당 총 3회까지 가능합니다.
횟수를 소진하면 영상 업로드 URL 발급이 403으로 거부됩니다.

=== AI 리포트 영상 업로드 URL 발급

link:{swagger-ui}#/AI/ai-video-upload-url[▶ Swagger에서 Try it out,window=swagger]

훈련 영상을 AWS S3에 직접 업로드하기 위한 API입니다. 무료 체험 횟수를 검증한 뒤 URL을 발급합니다.
최대 50MB(52428800바이트)까지 단일 `PUT`으로 올리며, `video/mp4`(mp4)와 `video/quicktime`(mov) 두 형식만 허용합니다.

발급과 동시에 `UPLOADING` 상태의 리포트가 만들어지고 그 `reportId`가 응답에 내려갑니다.
`reportId`를 잃어버려도 리포트 목록 조회로 다시 찾을 수 있습니다.

[IMPORTANT]
====
`uploadUrl`의 서명에는 `Content-Type`뿐 아니라 **`Content-Length`도 포함**되어 있습니다.
발급 요청의 `fileSizeBytes`와 정확히 같은 바이트 수로 `PUT`해야 하며,
`Content-Length` 없이(chunked transfer encoding) 보내면 S3가 403 `SignatureDoesNotMatch`로 거부합니다.

* React Native `fetch`에 `{uri, type, name}` 형태의 body를 넘기면 chunked로 전송되어 실패합니다.
* `react-native-blob-util`의 `RNFetchBlob.wrap(path)` 또는 Expo의
  `FileSystem.uploadAsync(url, uri, { httpMethod: 'PUT', uploadType: BINARY_CONTENT })`를 사용하세요.
* `Content-Length` 헤더를 직접 지정해도 플랫폼이 body 기준으로 덮어씁니다. 길이를 알 수 있는 body를 넘겨야 합니다.
* `fileSizeBytes`는 실제로 업로드할 파일을 stat해서 구합니다.
  URL 발급 후 압축·트랜스코딩하면 크기가 달라져 실패하므로 "압축 -> stat -> 발급 -> 즉시 PUT" 순서를 지키세요.
* `uploadUrl`이 만료되면 발급 API를 다시 호출해 새 URL을 받습니다.
====

operation::ai/video-upload-url[snippets='http-request,request-fields,http-response,response-fields']

==== 실패 응답

무료 체험 횟수(3회)를 소진하면 403(`AI_REPORT_TRIAL_EXCEEDED`)을 반환합니다.
파일 크기가 상한을 넘으면 `MEDIA_VIDEO_FILE_SIZE_EXCEEDED`, 0 이하면 `MEDIA_INVALID_VIDEO_FILE_SIZE`,
지원하지 않는 형식이면 `MEDIA_UNSUPPORTED_VIDEO_TYPE`을 400으로 반환합니다.

operation::ai/video-upload-url-error[snippets='http-response,response-fields']

NOTE: 업로드한 영상의 재생 URL 발급 API는 아직 없습니다. 비공개 버킷 운영을 확정하면 presigned GET 발급과
`objectKey` 소유자 검증을 함께 추가해야 합니다.

== Dog API

=== 강아지 등록

link:{swagger-ui}#/Dog/dog-register[▶ Swagger에서 Try it out,window=swagger]

온보딩 이후 강아지를 한 마리 추가로 등록합니다. 입력 항목과 검증 규칙은 온보딩 완료 요청의 `dogs[]` 항목과 같으며,
견종·성격은 온보딩 메타데이터의 `code`로 보냅니다.
사용자당 강아지는 **최대 5마리**까지 등록할 수 있습니다(삭제된 강아지는 세지 않음).
선택된 강아지가 없으면 등록하는 강아지가 선택(`SELECTED`)되고, 이미 있으면 `UNSELECTED`로 등록됩니다.
응답은 단건 조회와 같은 형태로 등록된 프로필을 201과 함께 내려줍니다.

operation::dog/register[snippets='http-request,request-fields,http-response,response-fields']

==== 실패 응답

강아지가 이미 5마리면 409(`DOG_LIMIT_EXCEEDED`)를 반환하며 강아지는 등록되지 않습니다.
잘못된 견종·성별·성격 코드는 400(`DOG_INVALID_BREED`, `DOG_INVALID_SEX`, `DOG_INVALID_PERSONALITY`)이며, 필수 입력 누락·형식 오류는 400(`BAD_REQUEST`)에 `errors` 필드로 항목별 원인이 내려갑니다.

operation::dog/register-error[snippets='http-response,response-fields']

=== 보유 강아지 목록 조회

link:{swagger-ui}#/Dog/dog-list[▶ Swagger에서 Try it out,window=swagger]

액세스 토큰으로 식별한 사용자가 보유한 강아지를 등록 순으로 모두 조회합니다. 강아지가 없으면 빈 배열(`[]`)을 반환합니다.
`status`가 `SELECTED`인 강아지가 현재 선택된 강아지이며, 사용자당 한 마리입니다.
견종(`breed`)과 성격(`personalities`)은 온보딩 메타데이터와 같은 `code`·`label` 쌍으로 내려가므로,
수정 화면은 `code`를 선택값으로, 표시 화면은 `label`을 그대로 사용합니다.
나이 미상 강아지는 `birthDate`·`age`가 `null`이고, 프로필 이미지·기대 사항을 등록하지 않은 강아지는 빈 문자열(`""`)입니다.

operation::dog/list[snippets='http-request,http-response,response-fields']

=== 강아지 프로필 수정

link:{swagger-ui}#/Dog/dog-update[▶ Swagger에서 Try it out,window=swagger]

사용자가 소유한 강아지 한 마리의 프로필을 요청 본문 값으로 **전체 교체**합니다.
수정 화면은 단건 조회 응답을 초기값으로 받아 모든 필드를 다시 보내며, 생략하거나 `null`로 보낸 선택 필드(`birthDate`, `personalities`, `profileImageUrl`, `expectation`)는 '값 없음'으로 저장됩니다.
선택 상태(`status`)는 이 API로 바뀌지 않습니다. 견종·성격은 온보딩 메타데이터의 `code`로 보내고, 응답은 단건 조회와 같은 형태로 수정된 프로필을 내려줍니다.

operation::dog/update[snippets='http-request,path-parameters,request-fields,http-response,response-fields']

==== 실패 응답

존재하지 않거나 본인 소유가 아닌 강아지를 요청하면 404(`DOG_NOT_FOUND`)를 반환합니다.
잘못된 견종·성별·성격 코드는 400(`DOG_INVALID_BREED`, `DOG_INVALID_SEX`, `DOG_INVALID_PERSONALITY`)이며, 필수 입력 누락·형식 오류는 400(`BAD_REQUEST`)에 `errors` 필드로 항목별 원인이 내려갑니다.

operation::dog/update-error[snippets='http-response,response-fields']

=== 강아지 프로필 삭제

link:{swagger-ui}#/Dog/dog-delete[▶ Swagger에서 Try it out,window=swagger]

사용자가 소유한 강아지 한 마리를 삭제합니다. 소프트 딜리트라 데이터는 남지만 이후 목록·단건·선택 강아지 조회에서 제외되며, 같은 강아지를 다시 삭제하면 404입니다.
선택 상태(`status`)는 다른 강아지로 넘어가지 않습니다. 선택된 강아지를 삭제하면 선택된 강아지가 없는 상태가 되고, 다음에 등록하는 강아지가 선택됩니다.
사용자의 강아지가 한 마리뿐이면 삭제할 수 없습니다.
응답 본문은 없습니다.

operation::dog/delete[snippets='http-request,path-parameters,http-response']

==== 실패 응답

존재하지 않거나 본인 소유가 아니거나 이미 삭제된 강아지를 요청하면 404(`DOG_NOT_FOUND`)를 반환합니다.

operation::dog/delete-error[snippets='http-response,response-fields']

마지막 남은 강아지를 삭제하면 409(`DOG_LAST_DOG_NOT_DELETABLE`)를 반환하며 강아지는 삭제되지 않습니다.

operation::dog/delete-last-dog-error[snippets='http-response,response-fields']

=== 선택된 강아지 프로필 이미지 조회

link:{swagger-ui}#/Dog/dog-profile-image[▶ Swagger에서 Try it out,window=swagger]

액세스 토큰으로 식별한 사용자가 선택한 강아지의 프로필 이미지 공개 URL을 조회합니다.
선택된 강아지는 사용자당 한 마리이며, 강아지를 처음 등록할 때(온보딩의 첫 강아지) 선택됩니다.
프로필 이미지를 등록하지 않은 강아지는 빈 문자열(`""`)로 내려가므로, 클라이언트가 기본 이미지를 표시합니다.

operation::dog/profile-image[snippets='http-request,http-response,response-fields']

==== 실패 응답

선택된 강아지가 없으면 404(`DOG_NOT_FOUND`)를 반환합니다. 온보딩을 마치지 않은 사용자가 여기에 해당합니다.

operation::dog/profile-image-error[snippets='http-response,response-fields']
